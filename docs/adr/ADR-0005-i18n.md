# ADR-0005: i18n — typed first-party dictionary, DE/EN parity at compile time, no runtime library

- **Status**: **Accepted (owner decision, 2026-11-22)**
- **Deciders**: owner (final), technical-director (author); copy ownership stays with the writer
- **Amends**: `docs/architecture.md` v1.2 — `i18n.svelte.ts`, Testing Strategy (i18n rows), Error-State Taxonomy, Accessibility Architecture; ratifies the language half of PRD F8/F9 and M4.
- **Related**: `ADR-0001` (no i18n dependency, bundle budget), `ADR-0003` (`lucky-elsa.lang.v2`), `ADR-0004` (`Localized` content), `design/accessibility-requirements.md`, `design/copy/copy-deck.md`

## Context

German and English ship from the first visit: German default, `?lang=en` overrides, the toggle
persists, and **zero untranslated strings** is a success metric (F8, M4), not a later pass. Two
kinds of text meet on one card: **chrome** (labels, state copy, announcements, errors) and
**content** (per-photo `name`/`mood`/`caption`/`alt`/`description`, authored in `captions.json`
and merged into the manifest).

v1 kept both in one `COPY.de`/`COPY.en` object and checked parity with a smoke script — drift was
found by eye. The constraints are: no third-party runtime request and no i18n dependency (PRD
§5/§7; ADR-0001), ≤ 60 KB JS gzip, WCAG 2.2 AA with bilingual announcements, copy authored by the
writer rather than invented in components. A runtime library is the conventional answer; here it
is the wrong one, because the guarantee needed is **compile-time completeness**, not formatting
power.

## Decision

### 1. Typed dictionary, two files, one type

`src/i18n/schema.ts` declares the closed key set and its placeholder shapes:

```ts
export type MessageKey = 'state.offline.nocache' | 'update.ready' | 'progress.label' | …;
export interface Vars { 'progress.label': { seen: string; total: string }; … }
export type Dictionary = { readonly [K in MessageKey]: string };
```

`de.ts` is the **master** (`const DE: Dictionary` — a missing key is a type error); `en.ts` is
`satisfies Dictionary` — a missing key is a compile error, an unknown key an excess-property
error. `LOCALES = ['de','en'] as const` derives `Locale`. Keys are namespaced by surface
(`app.*`, `state.*`, `card.*`, `collection.*`, `update.*`, `a11y.*`).

### 2. Typed substitution, native formatting

`t(key, vars?)` derives `vars` from the key, so a wrong placeholder set is a compile error and a
key declared without placeholders rejects a second argument. Placeholders are `{name}` tokens.
Counts and dates use the platform — `Intl.PluralRules` / `NumberFormat` / `DateTimeFormat` —
behind one cached helper in `src/i18n/format.ts`: built-in, zero dependency bytes. Plural keys
declare `one`/`other` explicitly; there is no ICU parser. Unresolved `{token}` output fails a
unit test rather than reaching a visitor.

### 3. Content is not dictionary

Manifest content is `Localized = string | {de,en}` (ADR-0004), resolved by one helper:

```ts
pickLocalized(value: Localized, lang: Locale): { text: string; fellBack: boolean }
```

A missing `en` falls back to `de` **and counts** (a test asserts the counter drains to zero
before release). A content string is never a dictionary key, and a key never appears in
`captions.json` — the two systems cannot substitute for each other.

### 4. Resolution order (F9) and persistence

1. `?lang=de|en` — the only accepted values; anything else is ignored silently (no error state).
   It applies to the visit and is **not** written to storage: a shared link must not rewrite a
   visitor's preference.
2. `lucky-elsa.lang.v2` (ADR-0003).
3. `de`.

An explicit toggle calls `setLang()`, which persists, sets `<html lang>`, updates
`<title>`/`og:locale`, re-renders every consumer (the dictionary is a reactive dependency) and
announces once in the **new** language.

### 5. Surface rules

- `<html lang>` always current; `dir="ltr"` fixed (no RTL locale in scope, F33).
- Per-element `lang` where DE/EN genuinely mix inside one card (PRD §5).
- Every announcement, `aria-label`, rarity label and state string goes through `t()` — an
  announcement in the wrong language is a bug, not a nuance.
- The no-JS `<noscript>` notice is bilingual in `index.html` (static exception; a test asserts it
  matches both dictionary entries).
- Strings live only in `src/i18n/` and the copy deck. A grep gate fails the build on a quoted
  German or English sentence inside `src/**/*.svelte` or a store.

### 6. Growth and budget

The copy deck is the authoring source; the typed dictionary is the shipped artefact (deck → TS,
one direction, never parsed at runtime). If the first real build exceeds the JS budget, EN becomes
a lazy `import()` chunk behind the same `Dictionary` type — no component or store change. More
locales are out of scope (F33); adding one extends `LOCALES` and the plural forms, and the parity
guarantee carries over.

## Consequences

**Positive** — "0 untranslated strings" is a build failure, not a review task; zero dependency,
zero extra request, no cookie, no locale negotiation; typed placeholders kill the mismatched-`vars`
class of defect and let the interaction-copy audit enumerate every user-visible string; the
dictionary is greppable and diffable.

**Negative / accepted costs** — every new string is two edits, with the compiler as the gate
(stronger than v1's script); no ICU plural/select syntax, so a complex grammatical case needs
per-key forms — sufficient for two languages and a controlled register, and documented rather than
hidden; no fallback chain beyond DE, deliberately; the static `<noscript>` text sits outside the
dictionary and can drift (one test covers it); tone (`du`, never `Sie`) stays a review/ownership
rule, because a compiler cannot enforce register.

## Performance Implications

Chrome strings are a few KB per locale, inlined and compressed with the bundle: no fetch, no
hydration, no runtime parser. `t()` is a property lookup plus a small `String.replace`; `Intl`
instances are cached per locale, so per-render formatting does not allocate. If the budget
tightens, the EN chunk is the first lever and copy shortening the second — never a library.

## Alternatives Considered

| Alternative | Why rejected |
| --- | --- |
| `svelte-i18n` | Runtime store + message compiler for two locales; missing keys are a console warning, not a build failure — the drift M4 forbids. |
| `i18next` | Large surface (plugins, loaders, interpolation engine) aimed at runtime catalogues; unused features are bundle and audit cost. |
| `typesafe-i18n` | Closest fit, but adds a generator step and its own syntax; the master + `satisfies` pair gives the same guarantee with no toolchain layer. |
| FormatJS / ICU MessageFormat | Powerful for plurals/gender/RTL, needs a compiler and message AST; two languages and a controlled register do not justify it, and native `Intl.PluralRules` covers the cases. |
| Runtime JSON fetch per locale | A round trip before first paint, a second cache surface, a flash of untranslated UI — and it breaks the instant-boot budget. |
| Per-component inline copy with `{#if lang}` | No single audit surface, no completeness guarantee, copy owned by whoever touched the component last. |
| Server-rendered per-locale HTML | No server build or SSR by decision (ADR-0001); doubles artefacts. |
| `?lang=` persists automatically | A shared link would permanently flip a visitor's language; only the toggle writes. |
